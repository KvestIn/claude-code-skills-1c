# /form-code - доработка формы в расширении

Код доработки формы по памяти пишется с ошибками: в решениях задач встречались выдуманные сигнатуры
(`Элементы.Добавить` с четырьмя параметрами), пути к данным мимо реквизитов, обработчики, не привязанные к
событию, и заимствованные формы, которые не загружаются. Не пиши этот код сам - опиши
доработку в JSON и запусти генератор. Он сверит имена с выгрузкой конфигурации и формой, заимствует форму,
при необходимости добавит реквизит объекту в расширении и напишет модуль формы по приемам, проверенным
загрузкой в Демо БСП 8.5.1 и синтаксическим контролем (обычным и расширенным).

Постановки, которые решаются этим навыком: "программно добавь на форму", "при создании формы на сервере
добавить надпись", "реквизит формы, который создается в коде", "оформление задать кодом", "в расширении добавь
на форму кнопку / поле". Форма типового объекта на поддержке - дорабатывается только в расширении, не правкой
модуля формы основной конфигурации.

## Когда НЕ применять

- Форма своей обработки или своего объекта (не типового) - навыки `1c-form-compile`, `1c-form-edit`.
- Логика модуля объекта или менеджера (проверка при записи, проведение) - перехват в модуле объекта.
- Печатная форма - навык `1c-print-form`; загрузка из файла - `1c-file-upload`.

## Генератор - основной путь

**Вызов навыка генератор не запускает.** Навык только выдает эту инструкцию; аргументы навыку не передаются.
Порядок: 1) запиши описание JSON в файл (Write); 2) запусти генератор командой Bash ниже; 3) убедись, что в выводе
есть строка `[OK] Доработка формы`. Нет этой строки - доработка не сделана, и сообщать о выполнении нельзя (было:
навык вызван дважды с аргументами, скрипт не запускался, модуль пустой, в отчете "выполнено").

Описание клади во временный каталог, не в проект. Один запуск - одна форма; генератор пишет модуль
заимствованной формы целиком и откажет, если модуль уже не пустой.

```bash
python "$HOME/.claude/skills/1c-form-code/scripts/form-code-gen.py" -SpecPath "<описание.json>"
```

```json
{
  "configPath": "C:/путь/к/выгрузке",
  "extension": {"path": "C:/путь/к/расширению", "name": "ICOM_Доработки"},
  "object": "Document._ДемоЗаказПокупателя",
  "form": "ФормаДокумента",
  "objectAttributes": [{"name": "КомментарийДляСклада", "type": "string(200)", "title": "Комментарий для склада"}],
  "elements": [
    {"kind": "group", "name": "Дополнительно", "title": "Дополнительно", "after": "Контрагент"},
    {"kind": "field", "name": "Примечание", "type": "string(1000)", "title": "Примечание", "into": "Дополнительно",
     "multiline": true, "load": "Комментарий", "save": "Комментарий"},
    {"kind": "field", "name": "КомментарийДляСклада", "objectAttribute": "КомментарийДляСклада", "after": "Комментарий"},
    {"kind": "label", "name": "ДолгКонтрагента", "after": "Контрагент",
     "query": "ВЫБРАТЬ\n\tСУММА(...) КАК Значение\nИЗ\n\t...\nГДЕ\n\t... = &Контрагент",
     "params": {"Контрагент": "Объект.Контрагент"}, "template": "Долг: %1", "format": "ЧДЦ=2; ЧН=0",
     "refreshOn": ["Контрагент"]},
    {"kind": "table", "name": "ПоследниеЗаказы", "title": "Последние заказы", "after": "Комментарий", "height": 5,
     "query": "ВЫБРАТЬ ПЕРВЫЕ 10\n\tЗаказы.Дата КАК Дата, ...\nУПОРЯДОЧИТЬ ПО\n\tЗаказы.Дата УБЫВ",
     "params": {"Контрагент": "Объект.Ссылка"},
     "columns": [{"name": "Дата", "type": "dateTime", "title": "Дата"}]},
    {"kind": "button", "name": "ПересчитатьСуммы", "title": "Пересчитать суммы",
     "recalc": {"table": "Товары", "set": "Сумма", "expr": "Количество * Цена", "total": "СуммаДокумента"}}
  ],
  "onChange": [{"field": "Контрагент", "clearIfOwnerDiffers": {"field": "Договор"}}],
  "appearance": [{"list": "Список", "filter": {"field": "Проведен", "value": false},
                  "set": {"ЦветТекста": "WebЦвета.Серый"}}],
  "intercepts": [{"method": "КонтрагентПриИзменении", "type": "После", "body": ["ОбновитьЦены();"]}]
}
```

Нужны только те разделы, что требует задача. Имена элементов, реквизитов формы и объекта генератор сам
дополняет префиксом расширения.

| Ключ | Что делает |
|---|---|
| `after` / `into` | место элемента: после элемента формы или внутрь группы (имена - из формы или из описания) |
| `field.data` | поле реквизита объекта: `Объект.<Реквизит>` |
| `field.objectAttribute` | поле нового реквизита объекта из `objectAttributes` (реквизит добавляется в расширении) |
| `field.type` | реквизит формы, создаваемый в коде; `load` - значение из реквизита объекта при создании формы, `save` - перенос в объект перед записью |
| `label.query` | запрос выбирает одно поле `КАК Значение`; `refreshOn` - поля, при изменении которых надпись пересчитывается |
| `table.query` | поля запроса `КАК <колонка>` для каждой колонки; таблица только для просмотра, заполняется при создании формы |
| `button.recalc` | пересчет колонки табличной части по выражению из ее колонок, `total` - итог в реквизит шапки |
| `button.body` | строки кода обработчика (клиент; `"server": true` - на сервере) - когда recalc не подходит |
| `onChange.clearIfOwnerDiffers` | очистка ссылки, если ее владелец (или реквизит `owner`) не равен полю |
| `onChange.body` | строки кода, по умолчанию на сервере (`"server": false` - на клиенте) |
| `appearance` | условное оформление динамического списка: отбор `filter`, параметры `set`, поля `fields` (пусто - вся строка) |
| `intercepts` | перехват существующего метода типовой формы: `method`, `type` После, Перед или Вместо (с `ПродолжитьВызов`), `body` - строки кода; `После` на `ПриСозданииНаСервере` объединяется с кодом генератора |

Типы: `string`, `string(N)`, `number(N,M)`, `date`, `dateTime`, `boolean`, `CatalogRef.X`, `DocumentRef.X`,
`EnumRef.X`. Параметр запроса - `Объект.<Реквизит>`, `Объект.Ссылка` или выражение BSL.

## Отказы - не обходи их

Генератор отказывает, если в выгрузке или на форме нет элемента, реквизита, табличной части, колонки или
таблицы из запроса, и перечисляет то, что есть. Такой отказ - ответ по существу: нужных данных в конфигурации
нет. Не придумывай реквизит и не пиши код в обход генератора - сообщи пользователю, чего не хватает, и
предложи вариант (например, в Демо БСП у заказа покупателя нет табличной части "Товары").

## Что генерируется

- `&После("ПриСозданииНаСервере")`: `ИзменитьРеквизиты`, `Элементы.Добавить` / `Элементы.Вставить`,
  `Команды.Добавить`, `УсловноеОформление`, заполнение надписей и таблиц.
- Поле с обработчиком изменения в форме - `&После("<обработчик>")`; поле без обработчика -
  `Элементы.<Поле>.УстановитьДействие("ПриИзменении", ...)`. Клиентский обработчик делает один серверный вызов.
- `&Перед("ПередЗаписьюНаСервере")` - перенос реквизита формы в объект.
- Событие, которого у типовой формы нет, добавляется в Form.xml заимствованной формы (навык `1c-form-edit`).

## Проверка

После генерации проверь расширение: загрузка в базу и синтаксический контроль модулей, обычный и
расширенный. Ошибка в модуле - меняй описание и запускай генератор заново на чистом модуле, а не правь код
руками.
