# /report-code - отчет на СКД

Запрос и схема отчета по памяти пишутся с ошибками: в решениях задач в виртуальную таблицу Остатки передавался
период вместо даты, диаграмма терялась, группировка шла не по тем полям, не было отбора по проведенным, а поле,
которого в конфигурации нет (вид цены), заменялось пустыми выдуманными справочником и регистром. Не пиши запрос и схему сам - опиши отчет в JSON и запусти генератор. Он сверит поля с выгрузкой,
построит текст запроса, соберет внешний отчет со схемой компоновки (навыки `1c-erf-init`, `1c-skd-compile`) и
проверит схему (`1c-skd-validate`).

**Вызов навыка генератор не запускает**: запиши описание JSON в файл (во временный каталог, не в проект) и
запусти команду Bash ниже; без строки `[OK]` в выводе работа не сделана.

```bash
python "$HOME/.claude/skills/1c-report-code/scripts/report-gen.py" -SpecPath "<описание.json>"
```

```json
{
  "configPath": "C:/путь/к/выгрузке",
  "outputDir": "C:/путь/src",
  "name": "ICOM_Продажи",
  "title": "Продажи по контрагентам",
  "source": {"document": "Document._ДемоРеализацияТоваров", "table": "Товары"},
  "dimensions": ["Контрагент", "Номенклатура", "Номенклатура.ВидНоменклатуры"],
  "resources": ["Количество", {"field": "Сумма", "expr": "Количество * Цена"}],
  "groupings": ["Контрагент", "Номенклатура"],
  "filters": ["НоменклатураВидНоменклатуры"],
  "chart": {"points": "Контрагент", "value": "Сумма"}
}
```

| Ключ | Что делает |
|---|---|
| `source.balance` | регистр накопления остатков: `Остатки(&Дата)`, параметр "На дату"; ресурс `Количество` читается как `КоличествоОстаток` |
| `source.turnovers` | регистр накопления: `Обороты(&НачалоПериода, &КонецПериода)`, параметр "Период" |
| `source.sliceLast` | периодический регистр сведений: `СрезПоследних(&Дата)` |
| `source.document` (+ `table`) | документ или его табличная часть за период, только проведенные (`"posted": false` - все); реквизиты шапки из табличной части берутся через `Ссылка` |
| `dimensions` | поля группировок и отборов; путь через ссылку - `Номенклатура.ВидНоменклатуры` (в отчете имя без точки) |
| `resources` | числовые поля с итогом (`agg`: Сумма, Количество, Максимум, Минимум, Среднее); `expr` - выражение из полей источника |
| `groupings` | порядок группировок (по умолчанию - dimensions); `"details": true` - детальные записи |
| `filters` | отборы, доступные пользователю в настройках отчета |
| `chart` | диаграмма: `points` и `series` из dimensions, `value` из resources |

## Отказы - не обходи их

Генератор отказывает, если в выгрузке нет объекта, поля, табличной части или ресурса регистра, и перечисляет то,
что есть. Нужных данных в конфигурации нет - построй отчет по тем, что есть, и прямо напиши пользователю, чего
не хватает (например, в Демо БСП в регистре цен нет вида цены). Не создавай справочники и регистры ради отчета.

## После генерации

Собери отчет навыком `1c-epf-build`: `-SourceFile <outputDir>/<name>.xml -OutputFile <name>.erf`.

## Когда НЕ применять

- Правка схемы существующего отчета (добавить отбор, поле, группировку) - навыки `1c-skd-edit`, для отчета
  типовой конфигурации - заимствование макета в расширение (`1c-cfe-borrow`) и `1c-skd-edit`.
- Нестандартный запрос (несколько источников, соединения, временные таблицы) - схема вручную навыком
  `1c-skd-compile`, запрос сверить навыком `1c-query-validate`.
