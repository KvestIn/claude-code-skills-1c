# /group-processing - групповая обработка объектов

Групповые обработки по памяти пишутся с ошибками: в решениях задач модуль обращался к реквизитам, которых нет
в обработке, лежал не по тому пути, у реквизита формы вызывались несуществующие методы, запись шла без обработки
ошибок и без учета проведенности документа (оценка 16.10.2026). Не пиши обработку сам - опиши ее в JSON и запусти
генератор. Он сверит объект, реквизиты и регистр с выгрузкой, построит запрос отбора и соберет обработку с формой
(навыки `1c-epf-scaffold`, `1c-epf-add-form`, `1c-form-compile`).

**Вызов навыка генератор не запускает**: запиши описание JSON в файл (во временный каталог, не в проект) и
запусти команду Bash ниже; без строки `[OK]` в выводе работа не сделана.

```bash
python "$HOME/.claude/skills/1c-group-processing/scripts/group-gen.py" -SpecPath "<описание.json>"
```

```json
{
  "configPath": "C:/путь/к/выгрузке",
  "outputDir": "C:/путь/src",
  "name": "ICOM_СменаОтветственного",
  "title": "Смена ответственного в заказах",
  "object": "Document._ДемоЗаказПокупателя",
  "params": [{"name": "НовыйОтветственный", "type": "CatalogRef.Пользователи", "title": "Новый ответственный"}],
  "selection": {"posted": null, "conditions": [{"field": "Ответственный", "op": "<>", "param": "НовыйОтветственный"}]},
  "columns": ["Дата", "Номер", "Контрагент", "Ответственный"],
  "action": {"kind": "set", "set": {"Ответственный": "param:НовыйОтветственный"}},
  "actionTitle": "Заменить ответственного"
}
```

| Ключ | Что делает |
|---|---|
| `object` | `Document.<Имя>` или `Catalog.<Имя>` |
| `params` | поля на форме: `date`, `dateTime`, `boolean`, `string`, `number`, `CatalogRef.X`, `DocumentRef.X`, `EnumRef.X`; `required` (по умолчанию да) проверяется до выполнения |
| `selection.period` | для документов - период "с ... по" на форме (по умолчанию да) |
| `selection.posted` | `true` - только проведенные, `false` - только непроведенные, не задан - все |
| `selection.conditions` | условия по реквизитам: `op` `=` или `<>` с `param` (поле формы) или булевым `value`; `empty` - реквизит не заполнен |
| `selection.noMovements` | нет движений по регистру за `days` дней: `register`, `dimension` - измерение со ссылкой на объект |
| `selection.excludeGroups` | для иерархического справочника группы исключаются (по умолчанию да) |
| `columns` | реквизиты, видимые в списке |
| `action.kind` | `set` - заполнить реквизиты (`set`: реквизит -> `"param:<Имя>"` или булево), `markDeletion` - пометить на удаление, `repost` - перепровести |
| `confirm` | вопрос перед выполнением (по умолчанию да), `question` - его текст |

Что делает обработка: "Заполнить" строит список по отбору (все отмечены), "Отметить все" и "Снять отметки",
действие - по каждому отмеченному объекту в `Попытка` с блокировкой объекта; проведенный документ записывается с
проведением, непроведенный - записью; ошибки (объект и текст) попадают в таблицу на форме и в журнал регистрации,
итог - сообщением. Помеченные на удаление объекты в отбор не попадают.

## Отказы - не обходи их

Генератор отказывает, если в выгрузке нет объекта, реквизита, регистра или измерения, и перечисляет то, что есть.
Нужных данных нет - сообщи пользователю, не создавай реквизиты ради обработки.

## После генерации

Собери обработку навыком `1c-epf-build`: `-SourceFile <outputDir>/<name>.xml -OutputFile <name>.epf`.

## Когда НЕ применять

- Загрузка данных из файла - `1c-file-upload`.
- Создание документов по другим объектам (ввод на основании) - `1c-command-code`.
- Действие, которое генератор не описывает (расчеты, запись в регистры) - обработка вручную по навыкам
  `1c-epf-scaffold` и `1c-form-compile`.
