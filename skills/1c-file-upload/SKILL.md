# /file-upload - загрузка файла с клиента на сервер

Файл, который пользователь выбрал на клиенте, на сервере по тому же пути недоступен: клиент и сервер - разные
компьютеры, а в веб-клиенте пути нет вовсе. Файл передается через временное хранилище. Этот механизм
по памяти пишется неверно почти всегда: из 11 решений задач загрузки ни одно не работало (13.10.2026) -
неверные параметры `НачатьПомещениеФайлаНаСервер` и `ПоместитьФайлНаСерверАсинх` или чтение файла на
сервере по клиентскому пути. Не пиши этот код сам - бери образец ниже.

## Генератор - основной путь для обработки загрузки

Опиши загрузку в JSON (файл во временном каталоге, не в проекте) и запусти генератор. Он сверит описание с
выгрузкой и соберет внешнюю обработку целиком: каркас, форму с параметрами, кнопкой и таблицей ошибок, модуль -
выбор файла по образцу ниже, чтение на сервере, поиск ссылок одним запросом на файл, запись, счетчики.

```bash
python "$HOME/.claude/skills/1c-file-upload/scripts/load-gen.py" -SpecPath "<описание.json>"
```

```json
{
  "configPath": "<каталог выгрузки конфигурации>",
  "outputDir": "<каталог src для обработки>",
  "name": "ЗагрузкаЦенИзExcel",
  "title": "Загрузка цен из Excel",
  "source": { "format": "excel", "header": true,
              "columns": [ { "name": "Артикул", "col": 1 }, { "name": "Цена", "col": 2 } ] },
  "params": [ { "name": "Дата", "type": "date", "title": "Дата цен" } ],
  "target": { "kind": "register", "object": "InformationRegister.ЦеныНоменклатуры",
              "set": { "Период": "param:Дата",
                       "Номенклатура": { "lookup": "Catalog.Номенклатура", "by": "Артикул", "value": "Артикул" },
                       "Цена": "Цена" } }
}
```

| Ключ | Что это |
|---|---|
| `source.format` | `csv` (`delimiter`, `encoding` UTF8 или ANSI, `header`), `excel` (`header`), `json` (массив объектов) |
| `source.columns` | `name` - имя значения в коде (идентификатор); `col` - номер колонки с 1 (CSV, Excel) или `key` - поле объекта (JSON) |
| `params` | поля на форме: `date`, `string`, `number`, `CatalogRef.<Имя>`; обязательные проверяются до выбора файла |
| `target.kind` | `catalog` - справочник: `key` (реквизит и колонка поиска), `mode` upsert, create или update, `set`; `register` - регистр сведений: `set` по измерениям, ресурсам и `Период`; `document` - документы: `header`, `table`, `rows`, `groupBy` (документ на каждое значение колонки), `post` |
| значение в `set`, `header`, `rows` | имя колонки, `"param:<Имя>"` или поиск ссылки `{ "lookup": "Catalog.<Имя>", "by": "<реквизит>", "value": "<колонка>" }` |

Режим справочника выбирай по постановке: "добавить только новые", "не трогать существующие" - `create`
(найденный по ключу элемент пропускается); "обновить существующие" - `update`; "загрузить и обновить" - `upsert`.
(Задача load-4 15.10.2026: просили только недостающие, выбран upsert - существующие перезаписаны.)

Пути - абсолютные или относительно файла описания. Числа из файла приводятся к числу (запятая или точка), ссылка,
которую не нашли, и ошибка записи попадают в таблицу ошибок на форме с номером строки.

**Отказ генератора - это ответ, а не ошибка, которую надо обойти.** Нет реквизита, измерения или табличной части -
генератор перечислит то, что есть. Не добавляй реквизит в конфигурацию ради загрузки: загрузи то, что можно,
и прямо напиши пользователю, какое значение из файла сохранить некуда (например, вида цены нет в регистре цен).

После генератора: собери обработку навыком `1c-epf-build`; нестандартный разбор значений допиши в модуле формы.
Проверено (15.10.2026) на Демо БСП: четыре вида загрузки (регистр из Excel, справочник из CSV и JSON, документы из
Excel с группировкой) - сборка, синтаксический контроль модулей обычный и расширенный, компиляция запросов,
проверки хука завершения.

Ниже - образец передачи файла, на котором построен генератор: для формы, которая уже есть, или своего формата.

## Когда применять

Конфигурация на БСП (есть общий модуль `ФайловаяСистемаКлиент` - проверь в выгрузке:
`CommonModules/ФайловаяСистемаКлиент`). Это все типовые конфигурации 1С. Для конфигурации без БСП образца
здесь нет - сообщи об этом пользователю, не пиши платформенные методы по памяти.

## Образец (модуль формы)

Три метода: команда на клиенте открывает диалог, обработчик завершения получает адрес файла во временном
хранилище, серверная функция пишет двоичные данные во временный файл и читает его. Проверен синтаксическим
контролем платформы (тонкий клиент, сервер, внешнее соединение) на Демо БСП 8.5.1.

```bsl
&НаКлиенте
Процедура ЗагрузитьИзФайла(Команда)
	
	ПараметрыЗагрузки = ФайловаяСистемаКлиент.ПараметрыЗагрузкиФайла();
	ПараметрыЗагрузки.ИдентификаторФормы = УникальныйИдентификатор;
	ПараметрыЗагрузки.Диалог.Заголовок = "Выберите файл для загрузки";
	ПараметрыЗагрузки.Диалог.Фильтр = "Файлы CSV (*.csv)|*.csv|Все файлы (*.*)|*.*";
	
	Оповещение = Новый ОписаниеОповещения("ЗагрузитьИзФайлаЗавершение", ЭтотОбъект);
	ФайловаяСистемаКлиент.ЗагрузитьФайл(Оповещение, ПараметрыЗагрузки);
	
КонецПроцедуры

&НаКлиенте
Процедура ЗагрузитьИзФайлаЗавершение(ПомещенныйФайл, ДополнительныеПараметры) Экспорт
	
	Если ПомещенныйФайл = Неопределено Тогда
		Возврат;
	КонецЕсли;
	
	Итоги = ЗагрузитьИзФайлаНаСервере(ПомещенныйФайл.Хранение);
	ОбщегоНазначенияКлиент.СообщитьПользователю(Итоги);
	
КонецПроцедуры

&НаСервереБезКонтекста
Функция ЗагрузитьИзФайлаНаСервере(Адрес)
	
	ДвоичныеДанные = ПолучитьИзВременногоХранилища(Адрес);
	ИмяВременногоФайла = ПолучитьИмяВременногоФайла("csv");
	ДвоичныеДанные.Записать(ИмяВременногоФайла);
	
	Чтение = Новый ЧтениеТекста(ИмяВременногоФайла, КодировкаТекста.UTF8);
	Строка = Чтение.ПрочитатьСтроку();
	Количество = 0;
	Пока Строка <> Неопределено Цикл
		Количество = Количество + 1;
		Строка = Чтение.ПрочитатьСтроку();
	КонецЦикла;
	Чтение.Закрыть();
	
	УдалитьФайлы(ИмяВременногоФайла);
	
	Возврат СтрШаблон("Прочитано строк: %1", Количество);
	
КонецФункции
```

## Что менять под задачу

| Что | Где |
|---|---|
| Фильтр и заголовок диалога | `ПараметрыЗагрузки.Диалог.Фильтр`, `.Заголовок`; Excel - `"Файлы Excel (*.xlsx;*.xls)\|*.xlsx;*.xls"` |
| Расширение временного файла | `ПолучитьИмяВременногоФайла("xlsx")` - по типу файла |
| Чтение | тело серверной функции между `Записать` и `УдалитьФайлы`: CSV и TXT - `ЧтениеТекста` (кодировку уточни у задачи: UTF8 или ANSI); Excel - `ТабличныйДокумент.Прочитать(ИмяВременногоФайла)`; JSON - `ЧтениеJSON.ОткрытьФайл` и `ПрочитатьJSON`; XML - `ЧтениеXML.ОткрытьФайл` |
| Запись данных в базу | в той же серверной функции или в модуле объекта обработки; результат (сколько создано и обновлено) вернуть строкой или структурой |

## Правила

- Имя процедуры-обработчика в `Новый ОписаниеОповещения("...")` совпадает с именем процедуры
  `...Завершение`, и она объявлена с `Экспорт` - иначе оповещение не вызовется.
- Команду `ЗагрузитьИзФайла` добавь на форму навыком `1c-form-edit` (команда с `Action` на эту процедуру и
  кнопка), а не только процедуру в модуль.
- Путь к файлу как строку на сервер не передавай и `Новый Файл(...)`, `ЧтениеТекста(...)` с клиентским
  путем на сервере не открывай - хук проверки блокирует такое чтение.
- Временный файл удаляй (`УдалитьФайлы`) после чтения.
- В модуле формы внешней обработки код работы с данными базы - в `&НаСервереБезКонтекста` или в модуле
  объекта, клиентские общие модули (`...Клиент`) - только в методах `&НаКлиенте`.
