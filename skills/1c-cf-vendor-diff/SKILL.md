# /cf-vendor-diff - Отличия конфигурации от конфигурации поставщика

Отвечает на вопрос "что тут меняли относительно типовой". Сравнение делает Конфигуратор (пакетный
`/CompareCfg`, то же, что "Конфигурация - Поддержка - Сравнить с конфигурацией поставщика"), скрипт разбирает
отчет: какие объекты добавлены, удалены, изменены; для правок кода - в каком методе они стоят (по выгрузке
конфигурации). Результат - сводка и по файлу на объект, чтобы читать по частям.

**Не угадывай доработки по именам объектов и не сравнивай выгрузку "на глаз".** В типовых конфигурациях
тысячи объектов с отраслевыми и государственными названиями (ЗЕРНО, ЕИС, ИСМП, ЭДО) - это типовой состав, а не
доработки. Доработки - только то, что есть в отчете сравнения.

## Порядок

1. Запусти скрипт (база - копия базы заказчика, Конфигуратор с ней должен быть закрыт):

   ```bash
   python "$HOME/.claude/skills/1c-cf-vendor-diff/scripts/vendor-diff.py" -InfoBasePath "<каталог базы>" -ConfigPath "<выгрузка>" -OutDir "$TEMP/vendor-diff"
   ```

   Каталог результата - вне выгрузки (`$TEMP/vendor-diff`): в выгрузке он смешается с файлами конфигурации.
   Удалять его после ответа не нужно.

   Работа сделана, только если скрипт напечатал строку `[OK] Отличий: ...`. Сравнение УТ - 2-3 минуты.

2. Прочитай `<каталог результата>/summary.md`: группы "Новые объекты", "Удаленные", "Изменен код",
   "Изменены свойства, состав или формы", "Отличаются только значения".

3. Для каждого объекта из групп с кодом и свойствами прочитай его файл `objects/NNN-<объект>.md`. Если отличий
   много (больше 30 объектов), иди по группам и отвечай частями; не читай `report-full.txt` целиком.

4. Если нужно понять, что делает измененный код, - прочитай метод в выгрузке (имя метода и строки указаны в
   файле объекта).

5. Ответ: только то, что есть в файлах объектов (тип нового реквизита, назначение формы и т.п. - если их нет в
   отчете, посмотри в выгрузке или не пиши). По каждому объекту - что изменено (новый реквизит, правка метода, новый метод, элемент формы), где
   (метод, форма), что делает доработка - коротко, по коду. Отдельно - группа "Отличаются только значения": это
   часто пересохраненные макеты и настройки, а не доработки; так и скажи, не придумывай им смысл.

Критерий завершения: описан каждый объект из сводки summary.md (или явно сказано, какие группы оставлены на
следующий ответ), ничего не добавлено сверх отчета.

## Параметры скрипта

| Параметр | Описание |
|---|---|
| `-InfoBasePath` | каталог файловой базы (или `-InfoBaseServer` + `-InfoBaseRef` для серверной) |
| `-UserName`, `-Password` | пользователь базы, если есть |
| `-ConfigPath` | XML-выгрузка этой конфигурации: из нее берется имя поставщика и находятся методы для правок кода |
| `-OutDir` | каталог результата (создается, `objects/` перезаписывается) |
| `-VendorName` | имя конфигурации поставщика, если не совпадает с `Name` из `Configuration.xml` выгрузки |
| `-VendorCf` | файл `.cf` поставщика той же версии - если конфигурации поставщика в базе нет |
| `-ReportFile` | готовый отчет сравнения (txt, UTF-16 или UTF-8) вместо запуска Конфигуратора |
| `-V8Path` | каталог `bin` платформы; по умолчанию - самая новая в `C:\Program Files\1cv8` |

## Отказы

| Сообщение | Причина | Что делать |
|---|---|---|
| `Конфигурация поставщика недоступна` | в базе нет конфигурации поставщика (база собрана из XML без `.cf` поставщика, конфигурация снята с поддержки) | `-VendorCf` с файлом типовой той же версии - спросить у пользователя, где он |
| `Не указано имя конфигурации поставщика` | имя не совпало с `Name` выгрузки | `-VendorName` - имя из `Ext/ParentConfigurations.bin` (навык `1c-support-state` его печатает) |
| база заблокирована | открыта в Конфигураторе или клиенте | попросить пользователя закрыть сеансы |

## Что в отчете считается чем

- `***` - объект изменен, `<---` - есть только в основной конфигурации (добавлен заказчиком), `-->` - есть только
  у поставщика (удален заказчиком), `^` - изменен порядок.
- "Объект присутствует только в основной конфигурации: N - M" у модуля - строки N-M добавлены в модуль
  заказчика; скрипт дописывает метод, в котором они стоят, или "новые методы".
- "Объект присутствует только в конфигурации поставщика" - строки удалены из типового кода (их текст в отчете).
- Версия типовой важна: если заказчик не обновлен до версии поставщика из `-VendorCf`, в отчет попадут
  изменения обновления.
